# Subway Route Finder
---

## 프로젝트 개요

- **환경** : C++ / Visual Studio
- **형태** : Console Application
- **데이터** : CSV 기반 지하철 노선 데이터

**핵심 구현**
- CSV 데이터 생성 및 파싱
- Graph 기반 노선 구성
- BFS 경로 탐색
- 다익스트라 최소시간 탐색
- 환승 패널티 적용
- 경로 및 환승역 출력
- 기능별 클래스 분리

---

## 01. 초기 설계

CSV 데이터를 읽어 노선 정보를 `SubwayData` 형태로 저장

**SubwayData**
- 호선
- 출발역
- 도착역
- 이동시간

CSV의 각 행을 파싱하여 하나의 'SubwayData'로 변환해 전체 노선 데이터를 'vector'에 순차적으로 저장 

---

## 02. BFS 기반 경로 탐색

 'vector'에 저장된 데이터를 기반으로 초기 경로 탐색 알고리즘으로 **BFS** 적용

### 탐색 과정
출발역을 큐에 추가 
→ `subwayDataList`를 순회하며 연결된 역 확인
→ 방문하지 않은 역을 큐에 추가 
→ 이전 역 정보 저장  
→ 도착역 확인 시 탐색 종료
→ 이전 역을 따라 경로 역추적 

### 문제점

BFS는 **이동시간**과 같은 가중치를 고려하지 않고 **이동 구간 수**를 기준으로 경로탐색
→ 동일한 구간 수에서도 실제 이동시간 차이 발생
→ 최소 소요시간을 구해야 하는 과제 요구사항과 맞지 않음

---

## 03. 다익스트라 알고리즘 적용

BFS는 이동시간 가중치를 반영하지 못했기에 
**역별 최소 소요시간을 관리하는 다익스트라 방식으로 변경**

### 탐색 과정
방문하지 않은 역 중 현재 소요시간이 가장 짧은 역을 선택
→ 연결된 역의 이동시간 계산
→ 기존 시간보다 짧으면 최소시간 갱신 
→ 도착역까지 반복

경로 탐색 시 전체 노선 데이터를 반복해서 순회하지 않도록
역별 연결 정보를 관리하는 **그래프 구조**로 변경

**SubwayData**
- 연결된 역
- 호선
- 이동시간

## 04. 환승 패널티 적용

이전 이동에 사용한 호선을 저장하고 다음 호선과 비교  
→ **노선 변경 시 3분 추가**  
→ 환승시간을 포함한 총 소요시간 기준으로 경로 갱신

---

## 05. 구조 분리

기능 구현 후 클래스별 책임 분리

- **SubwayCSVLoader** : CSV 로드 및 파싱
- **SubwayDataManager** : 데이터 관리 및 Graph 구성
- **SubwayPathFinder** : 경로 탐색 및 다익스트라 처리
- **SubwayConsoleView** : 콘솔 결과 출력
  
데이터 관리, 경로 탐색, 출력 역할을 각각 분리함
